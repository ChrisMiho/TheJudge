## Changes

### Build pipeline (`build-game-rules.mjs`)

When building `gameRulesRuleIndex.json`, also emit `gameRulesTokenStats.json`:

```json
{
  "N": 3432,
  "tokens": {
    "cascade": { "df": 12 },
    "deathtouch": { "df": 8 }
  }
}
```

- `N` = total rules in index.
- `df` = count of rules whose `searchText` contains the token (same tokenization as scorer).
- Run build after manifest/index changes; commit generated stats file.

### Keyword vocabulary (`gameRulesKeywordVocabulary.json`)

Manual initial set — include at minimum tokens exercised by fixtures and common oracle keywords:

`cascade`, `prowess`, `deathtouch`, `lifelink`, `trample`, `flying`, `haste`, `hexproof`, `indestructible`, `menace`, `reach`, `vigilance`, `ward`, `flash`, `counter`, `destroy`, `exile`, `sacrifice`, `trigger`, `replacement`

Array of lowercase strings or `{ "tokens": [...] }` — pick one shape and load consistently.

### Scoring constants (tunable defaults)

```ts
const QUESTION_TOKEN_MULTIPLIER = 3;
const KEYWORD_TOKEN_MULTIPLIER = 6;
const SCORE_EXACT_RULE_ID = 100;
const SCORE_PARENT_RULE_ID = 20;
```

Remove `SCORE_TOKEN_MATCH` / `SCORE_DOTTED_TOKEN_MATCH` flat bonuses; dotted tokens use same IDF path as other tokens.

### Query provenance

Replace monolithic `buildQueryText` tokenization with:

```ts
export type QueryTokenSource = "question" | "oracle";

export function buildQueryTokens(context: PromptContext): {
  queryText: string;
  tokens: Array<{ token: string; source: QueryTokenSource; isKeyword: boolean }>;
  queryRuleIds: string[];
};
```

- `question` source: `context.finalQuestion` only.
- `oracle` source: turnPhase, selectedZones, stack/battlefield card fields and `contextNotes` (same fields as current `buildQueryText`).
- Keyword flag: token ∈ vocabulary (case-insensitive match on tokenized form).
- Keep `buildQueryText` as a thin concatenation for debug output if callers need the string.

### Per-token score contribution

For each matched token on an entry:

```
weight = log(N / max(df, 1))
if source === "question": weight *= QUESTION_TOKEN_MULTIPLIER
if isKeyword: weight *= KEYWORD_TOKEN_MULTIPLIER
score += weight
```

Load token stats once (mirror `ruleIndexCache` pattern). If stats file missing, log warn once and fall back to `df = 1` for all tokens.

### Tie-break

After sorting by total score descending:

1. Highest single-token IDF among tokens that matched this entry (use base IDF before multipliers for tie metric, or document if using weighted contribution — prefer **base IDF** for interpretability).
2. `parseFloat(ruleId)` ascending.

### Debug

`retrieveSupplementalRulesWithDebug` / `enrichmentDebug` continue exposing scores, selected, runnerUp. Extend debug payload with per-selected-rule matched-token summary if cheap (optional).

## Acceptance criteria

- [ ] `gameRulesTokenStats.json` generated by `node scripts/build-game-rules.mjs` and committed
- [ ] `gameRulesKeywordVocabulary.json` committed with fixture-relevant keywords
- [ ] Question-only token (e.g. `cascade` in question) outranks oracle-only noise for cascade fixture scenario in unit test
- [ ] Keyword token in oracle (e.g. `deathtouch` on creature) boosts relevant damage/deathtouch rules above generic low-number rules
- [ ] Exact rule id in question still gets +100; parent id match still gets +20

- [ ] `excludeRuleIds` from Slice A selection still applied; curated rules never in top-5
- [ ] `retrieveSupplementalRules` returns max 5 deduplicated rules
