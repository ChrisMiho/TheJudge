Production build (`npm --workspace apps/frontend run build`) served by `vite preview` on port 4931 (agent-owned); pre-change build (merge-base `a6b127da`, built from `git archive` into `.tmp/base/`) on port 4932 (agent-owned). Tap timing is rAF-sampled in the page: first frame with the tool's own element visible, and any frame showing "Loading…" or "Loading card list…".

One fix came out of this run: the first build scheduled the download when the page shell mounted, so tier 2 started while the Quick Question code was still arriving (tier 2 at 512 ms, before the screen at 819 ms). The scheduler now starts from inside the landing destination's boundary, so it runs only after the landing destination has rendered (test: "waits for a still-loading landing destination to render before starting the download").
