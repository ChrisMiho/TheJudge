History trigger relocation & full-bleed chat surface

Two changes on top of what already shipped: the history trigger moves into the corner rail, and the conversation thread stops living in a small boxed-in scroll area.

What's shown below is illustrative, not pixel-final — spacing, icon glyph, and exact bubble treatment are implementation details for mapping. The point of this mock is to confirm direction before any PRD text or code changes:
  • Does the history icon belong stacked directly under Menu, at this size, this close?
  • Does removing the boxed/capped thread in favor of a taller, higher-contrast chat column read as "closer to Claude" to you?

1. History trigger placement

Today: a full-width "Conversation history" button sits inside the workspace body, above the context trigger — this is exactly what DEC-125 specified, and the Menu rail's ambient glow hit-area (DEC-122, ~5.5rem × 10.5rem) belongs to Menu alone. Proposed: that same glow field grows taller and splits into two equal hit-zones — Menu on top, History below — only on the two destinations that have history to show.

2. Chat surface — full-bleed thread

Today: the thread is boxed inside its own bordered panel, capped at a small fixed height with internal scrolling, and bubble backgrounds barely differ from the surrounding card. Proposed: the thread fills the available height, the composer becomes a docked pill at the bottom, and user/assistant turns read as clearly distinct — closer to Claude's actual chat layout.

3. History drawer — still a sidebar, just on-demand

To be explicit about the question that came up: yes, it's still a sidebar — it docks flush to the left edge and slides in over the workspace, same as the Menu drawer does today. The only thing that changed earlier in this doc is that it doesn't stay permanently open on desktop like Claude's does; it opens on demand from the rail icon and closes the same way. What's different below is only the row styling inside it once it's open.
