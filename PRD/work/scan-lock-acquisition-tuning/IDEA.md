# scan-lock-acquisition-tuning

The latest scanner tuning trial changed the scan stabilizer from `windowSize: 6` / `minVotes: 4` to `windowSize: 13` / `minVotes: 3`, keeping `lockDistance: 78` and `marginMin: 14`; tests were updated so hook auto-add coverage uses the configured vote count and a new stabilizer regression proves three retained confident votes can lock. Owner retest after that change found scanning was still difficult to acquire, but once the card did identify, it locked quickly. That suggests the stabilizer convergence change improved the tail end of the pipeline, while the remaining bottleneck is still earlier: camera focus, detector corner quality, frame selection, frame-quality gating/cues, or identity confidence before votes begin. The desired outcome is a scanner that reaches the first reliable identity vote with less distance/lighting/position hunting while preserving the no-false-auto-add precision guard. Non-goals for this refinement: changing the hash recipe/bin format, rebuilding scan fingerprints, or loosening `lockDistance`/`marginMin` without diagnostic evidence.
