## Findings

1. **The clearing rule is ambiguous when only part of the carried work changes.** The brief ("clear the question, the cards and the `lookup` Draft only if they are unchanged since the carry") reads as all-or-nothing. The REQ-206 diff says "a question or card changed on Ask a Question after the carry is new staging and is kept", which reads as per-item. Criterion 5 tests only "text or the cards" changed, never one without the other. So a player who edits the question but leaves the carried cards (or the reverse) gets an undefined result: do the untouched cards leave the stage, or stay? Also undefined: what counts as "changed" (any difference from the carried snapshot, including emptying the box or a whitespace-only edit), and whether a box the player emptied after the carry still gets its Draft removed. Fix: state one rule in the brief, in the REQ-206 criterion and in the quick-lookup sentence (recommended: all-or-nothing, compare cards and trimmed question to the carried snapshot; any difference keeps everything and the Draft), and add a criterion that edits only the question, and only the cards, each keep both.

2. **The brief does not cover the owner's new evidence: type, clear, refresh, and the old message comes back.** The brief and `evidence/measurements.md` say type-then-clear does not reproduce, but they only tested clear-then-blur in one page session, never clear-then-reload. Typing or emptying the question runs none of these; there is no `pagehide`/`beforeunload` save anywhere in the frontend. So once any Draft exists (from an earlier Menu-leave, or a card attach), a player who empties the box and reloads without leaving the destination keeps the old stored Draft, and the mount effect (line 166) restores it. This is a second path, independent of the In-depth carry, and the brief's root cause and the REQ-206 amendment do not explain or fix it. Fix: add this path to the root cause and measurements (reproduce it live), state the rule (an emptied box with no cards removes the Draft at the moment it empties, or on page hide; recommend the former), and add a criterion: save a Draft via Menu-leave, return, clear the box, reload, and the box is empty with `thejudge.conversationDraft.lookup` absent. REQ-108/FLOW-017 text may need a one-line amendment in the GATE-QUESTIONS slot, since REQ-108 currently names only Menu-leave and reload as snapshot points.
