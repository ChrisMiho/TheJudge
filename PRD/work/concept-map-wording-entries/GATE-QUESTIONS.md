## REQ-234 — six more kinds of card wording point rule search at the right rules

**What this decides:** whether Luna's rule search learns six more kinds of card wording — "whenever", "rather than pay its mana cost", "gain control of", "gets −2/−2", "Sacrifice this creature:" and "Choose two —" — plus a clean-up of the type-setting wording it learned last time, and a written rule for which words a new entry may add.

**In plain terms:** before searching the rule book, the app reads each card's text through a fixed list of patterns, the concept map, and adds rule-book words for every pattern that matches (REQ-234: a committed table, one pattern per common card wording; no AI writes search words). Today it has 78 patterns. This adds six, so a card with those words also brings in "handling triggered abilities" (rule 603), "alternative cost casting" (118.9), "interaction of continuous effects" (613), "toughness state-based action" (704.5f/g), "activated ability cost" (602) or "casting spells" (601). A probe measured the six together, with every test question scored by a model that never saw it: deciding rules reaching Luna rose from 522 to 536 on one half of the practice questions and 511 to 522 on the other, and nothing fell. The intake says you approved these six by name on PR #293 on 2026-10-12; accepting this slot puts that review on record. Three smaller parts ride along. The type-setting pattern stops firing on "except the copy is an artifact" and on Un-card text where a counter is the subject. A new entry's words must be words the map already uses or a rule-book section title copied exactly; today's text says "no added terms", which three of the six would break. And In-Depth will add some curated rule topics for these cards (REQ-242 picks In-Depth's topics when a card's concept words match a topic's trigger words): the casting and cost wording brings the spell-casting topics, the layer wording the layer-order and timestamp topics. This is the designed path, and the build counts how many test cases it touches.

**What happens if you say no:** the map stays at 78 entries, the type-setting pattern keeps its few false matches, and nothing is retrained. To drop one entry instead, answer `edit` and name it; the build then re-measures the rest.

## REQ-236 — retrain the search model for the new map, and re-check the rules once per retrain

**What this decides:** whether to ship a search model retrained on the new map, and whether "re-check which deciding rules reach the prompt, once, after every retrain" becomes a standing rule instead of a one-time line.

**In plain terms:** the search model (REQ-236: a small model trained on Magic rules questions that ranks rules by meaning; its weights live in private storage, never in git) learned from search queries the concept map builds. Once the map changes, the model must be retrained on the new queries, or it ranks with old habits; REQ-236 already says training runs only after search changes land. The build retrains it with the unchanged recipe, rebuilds the saved vector files that name the model, and re-baselines the rules gate once (REQ-222: an offline check of which deciding rules reach the prompt across 415 test cases; re-baselining saves the new result as the bar). Today's REQ-236 says that re-baseline happens "in this change", meaning the last build; this makes it once per retrain, with every lost rule listed and the total not allowed to fall. The build parks rather than ship a model that scores below today's 522 on the check half. It also fills a gap from the last build: the rule text per prompt (7,478 characters per practice question, 4,412 per corpus case). Before you merge the code PR, you upload the new model to private storage with `docs/aws/model-upload.md`; the deploy refuses without it.

**What happens if you say no:** no retrain. If REQ-234 is accepted alone, the map change would ship on a model trained for the old queries, which REQ-236's own "train after search changes land" rule forbids, so the build would stop after the measurement step. Recommendation: accept or reject both slots together.
