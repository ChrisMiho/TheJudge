# IDEA: scan-detector-foil-robustness

**Problem:** The card-scan **detector** (`apps/frontend/src/lib/scan/detector.ts` `detectCard`) cannot reliably lock a stable 4-corner outline before matching runs. Confirmed on-device on two physically different cards: the ornate / etched-foil Japanese Strixhaven Mystical Archive `Akroma's Will`, **and** a plain non-Japanese English card held centered in the frame (2026-06-25). The debug overlay shows the shape never locks, so `detectCard()` returns `null` and the warp + fingerprint match never run (`ScanCameraSurface.tsx:130-145` → status `no-card`). This is upstream of matching: the fingerprint DB already contains the card (`soa/66` is `fingerprinted`), so it is purely a card-finding failure, not a corpus or language gap. The non-Japanese repro means the scope is **general detector robustness**, not foil-specific (despite the slug). Full diagnosis preserved in the cleanup receipt `PRD/instructions/receipts/scan-robustness-tuning-2026-06-25.md` and the `Camera capture & detector` known-limitation note in `PRD/sections/system-map.md`.

**Outcome:** The detector reliably finds and locks the card outline for ornate/foil/full-art printings under realistic lighting, so these cards reach the existing (unchanged) warp → Region A crop → fingerprint match → lock path and identify correctly. Likely levers to evaluate against real failing frames: Canny thresholds (`CANNY_LO/HI`), solidity/rectangularity gates (`SOLIDITY_MIN`, `RECTANGULARITY_MIN`), foil-glare-tolerant edge sourcing, adaptive/closing morphology, and a low-contrast-border detection assist — without weakening detection precision (no false card locks on non-card scenes).

**Non-goals:** No change to Region A recipe geometry (`recipe.ts` `cropRegionA`/`phashRegionPacked`) or the `CARDHSH1` bin format (those force a full DB rebuild — separate escalation), no change to `identify.ts` distance/orientation, the runtime stabilizer lock gate, or DEC-051/REQ-034 byte-exact parity. No OCR/text-recognition. No new corpus build (the card is already fingerprinted). First step is capturing a real failing frame, since `ScanCameraSurface` has no frame-export today.

**Source:** Escalated from `scan-robustness-tuning` (now closed out); root-cause evidence preserved in `PRD/instructions/receipts/scan-robustness-tuning-2026-06-25.md`.
